#### **Proje:** Versa Coder

1. Projenin Gerçek Amacı

Versa Coder, klasik bir IDE veya yalnızca ChatGPT benzeri bir kod asistanı olarak tasarlanmamalıdır. Senin tarif ettiğin sistemin asıl amacı, kullanıcının doğal dilde verdiği bir işi anlayan, bu işi parçalayan, uygun agent'ları seçen, gerekli araçları ve MCP servislerini belirleyen, session oluşturan, workflow kuran, gerektiğinde birden fazla agent'ı birlikte çalıştıran ve ortaya çıkan sonucu doğrulayıp kullanıcıya sunan tam kapsamlı bir Agentic Software Engineering Platform oluşturmaktır. Yani sistemin merkezinde editör değil, Agent + Session + Workflow + Tool + Memory + Model + Policy kombinasyonu bulunmalıdır. IDE/WinForms arayüzü bunun üzerinde çalışan yönetim ve kontrol katmanıdır.

Kullanıcı Chat Agent ekranında örneğin “Bu projeyi analiz et, mevcut mimariyi çıkar, eksikleri bul ve Clean Architecture'a göre refactor planı oluştur” dediğinde sistem yalnızca bu metni bir modele göndermemelidir. Önce kullanıcının niyetini anlamalı, işin risk seviyesini belirlemeli, gerekli yetenekleri çıkarmalı, uygun agent veya agent grubunu seçmeli, hangi repository'lere ve dosyalara erişileceğini belirlemeli, hangi araçların kullanılabileceğini hesaplamalı, gerekli MCP server'larını belirlemeli, session yapılandırmasını üretmeli ve ardından Session Agentic Agent Wizard üzerinden kullanıcıya bu yapılandırmayı göstermelidir. Kullanıcı onay verdiğinde ise sistem bu yapılandırmayı immutable bir session configuration olarak kaydedip gerçek agentic execution başlatmalıdır.

Buradaki en önemli nokta şudur: LLM sistemin kendisi değildir. LLM, Versa Coder'ın içinde kullanılan karar/üretim bileşenlerinden biridir. Asıl sistem; agent runtime, orchestration, policy engine, session management, tool gateway, memory, workflow engine, persistence ve observability katmanlarından oluşmalıdır. Böyle tasarlanmazsa proje kısa sürede büyük bir ChatService sınıfına dönüşür ve daha sonra agent, MCP, plugin, session, security ve workflow özelliklerini eklemek ciddi mimari borç oluşturur.
